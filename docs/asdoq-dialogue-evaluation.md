# ASDoQ v2.0aによる対話評価

## 目的

この文書は、タイ文字ノート開発におけるユーザーとCodexの対話を、`ASDoQ_SystemDocumentationQualityModel_v2.0a.xlsx` の内容に沿って評価する。

評価対象は、会話そのものを「開発文書として残す情報」と見なした場合の品質である。

## 参照したモデル

参照ファイル:

- `ASDoQ_SystemDocumentationQualityModel_v2.0a.xlsx`
- シート: `品質特性・副特性・測定項目（例・違反例を含む）`

このExcelに記載されている品質特性と品質副特性だけを用いる。

| 品質特性 | 品質副特性 |
|---|---|
| 目的適合性 | 目的明示性、目的合致性 |
| 保守性 | 再利用性、持続可能性 |
| 整合性 | 無矛盾性、一貫性、構造性 |
| 理解容易性 | 非曖昧性（一意性）、非曖昧性（識別性）、関係性 |
| 可読性 | 簡潔性、表記適切性、表現適切性 |
| 規範適合性 | 制約適合性、基準適合性、文法適合性、記法適合性 |

## 評価尺度

| 評価 | 意味 |
|---|---|
| A | 開発文書として十分に使いやすい |
| B | 概ね使えるが、補足文書があるとよい |
| C | 重要情報が不足し、引き継ぎ時に誤解が起きやすい |

## 日時の記録方法

- 発話日時は、ローカルに保存されたCodexセッションログのタイムスタンプを日本標準時（JST、UTC+9）へ変換して記録する。
- 実装日時は、Gitコミットに記録された日本標準時の日時を記録する。
- 各ターニングポイントでは、評価対象となった発話と実装記録を分けて示す。

## 結論

Excel版ASDoQ v2.0aに沿って見ると、ここまでの対話は「目的適合性」「整合性」「可読性」は比較的高い。

一方で、弱いのは「保守性」と「規範適合性」である。理由は、会話としては十分に機能していても、後から別環境・別セッションで再利用するための文書標準、用語集、表記ルール、表示制約の記録がまだ不足しているためである。

次に優先すべきことは、対話の内容を次の文書に分解して残すことである。

1. 引き継ぎ文書
2. 表記ルール文書
3. タイ文字表示の注意点文書
4. セットアップ文書
5. 用語集
